# 강원 시범 권역 계획 — 마스코트 가이드 탐방 (E안)

- 작성: 2026-11-26
- 상태: 초안 (사용자 확인 필요 항목은 맨 아래 "정할 것")
- 근거: 얼리어답터 설문 33명 (쿠폰 4.59, 가이드 퀘스트 4.19, 해금 4.03, 도감 3.97 / 망설임 이유 시간 75%·비용 72%), 의사결정표에서 E안 선택

## 1. 한 줄 방향

직접 가야 열리는 지도 위에서, 그 지역 마스코트가 명소·먹거리·특산품을 안내하고, 다녀온 기록이 도감으로 쌓이는 앱.

## 2. 시범에서 확인하려는 것

| 질문 | 확인 방법 |
|---|---|
| 마스코트 가이드가 실제 방문을 늘리는가 | 베타 참여자 중 시범 시·군을 실제로 해금한 비율 |
| 해금한 뒤 가이드 퀘스트까지 하는가 | 해금한 사람 중 퀘스트 1개 이상 완료 비율 |
| 잠긴 지역 미리보기가 방문 계기가 되는가 | 미리보기를 본 시·군과 실제 해금한 시·군 비교 |
| 마스코트 수집이 동기가 되는가 | 종료 설문 (수집 선호층과 비선호층 비교) |

목표치는 정하지 않았다 (정할 것 3번).

## 3. 범위

**시범 시·군 4곳 (제안)** — 서울에서 대중교통으로 당일치기가 되는 곳. 설문에서 '시간 부족'이 가장 큰 이유였기 때문.

| 코드 | 시·군 | 교통 (확인 필요) | 가이드 퀘스트 후보 (현지 확인 필요) |
|---|---|---|---|
| 51110 | 춘천시 | ITX-청춘, 경춘선 | 호수 산책 명소, 닭갈비·막국수, 지역 특산 이야기 |
| 51130 | 원주시 | KTX | 출렁다리 등 명소, 지역 먹거리, 한지 이야기 |
| 51150 | 강릉시 | KTX | 해변·정자 명소, 커피거리, 지역 먹거리 |
| 51210 | 속초시 | 고속버스 | 산·호수 명소, 시장 먹거리, 항구 이야기 |

- 강원의 나머지 14곳: 지금처럼 해금만 된다 (마스코트·퀘스트 없음, "준비 중" 표시).
- 다른 시·도: 변경 없음.
- 넣지 않는 것: 던전 탐험(보류), 재화·쿠폰(법률 검토 전), 서버, 사진 업로드, 동행 키우기(배터리 우려).

## 4. 콘텐츠

시·군마다:
- **마스코트 1종**: 이름, 한 줄 소개, 그림 1장(작은 PNG 또는 SVG). 지자체 공식 마스코트는 쓰지 않고 자체 캐릭터로 만든다 (저작권).
- **가이드 퀘스트 3개**: 명소 1, 먹거리 1, 이야기(특산품·역사) 1. 각각 제목, 마스코트 말투의 짧은 안내문(3~4문장), 인증 지점 좌표.
- **미리보기 문구**: 잠긴 상태에서 보여 줄 한두 줄.

합계: 마스코트 4종, 퀘스트 12개. 사실 정보(영업 여부, 위치)는 제작 후 한 번 더 확인한다.

## 5. 앱 변경 (지금 방식 그대로, 네이티브 플러그인 추가 없음)

1. **콘텐츠 데이터 파일** `assets/public/data/guide.js` (새 파일, 손으로 관리)
   ```js
   var GUIDE = {
     "51110": {
       mascot: { id:"m_51110", name:"…", intro:"…", img:"img/mascot/51110.png" },
       preview: "…",
       quests: [ { id:"q_51110_1", kind:"spot", title:"…", text:"…", lat:0, lon:0, radius:200 } ]
     }
   };
   ```
2. **저장 구조 v5**: `quests: { 퀘스트ID: {at, lon, lat, acc, test, via} }` 추가. 마스코트는 해금 기록에서 바로 계산하므로 따로 저장하지 않는다. v4→v5 이전은 `quests:{}` 추가뿐이고, 이전 키는 지우지 않는다 (CLAUDE.md 규칙).
3. **해금 연출**: 시범 시·군 해금 시 도장 뒤에 마스코트 등장 카드.
4. **지역 상세 시트**: 해금된 시범 시·군은 마스코트와 퀘스트 3개 목록. 퀘스트마다 "여기 왔어요" 버튼 → 위치 측정(정확도 100m 이내, 인증 지점 반경 안) → 완료 도장.
5. **잠긴 지역 미리보기**: 시범 시·군은 잠겨 있어도 마스코트 실루엣과 미리보기 문구, 퀘스트 제목만 보여 준다.
6. **도감**: 마스코트 카드 모음(4칸 + "준비 중"), 퀘스트 완료 수.
7. **베타 리포트 내보내기**(설정): 좌표를 빼고 해금·퀘스트 완료 날짜와 개수만 담은 짧은 텍스트. 참여자가 설문 폼에 붙여 넣는다. 기기 밖으로 좌표를 보내지 않는 원칙을 지키기 위함.
8. **개발용**: 테스트 모드의 가상 위치 목록에 퀘스트 인증 지점 추가.

## 6. 진행 순서

| 단계 | 할 일 | 끝났다고 보는 기준 |
|---|---|---|
| 0. 콘텐츠 초안 | 4곳 마스코트 콘셉트·퀘스트 12개 글·좌표 | 사용자 검토 통과 |
| 1. 데이터·저장 | guide.js, 저장 v5와 이전 | 기존 기록이 그대로 남는지 브라우저에서 확인 |
| 2. 화면 | 마스코트 등장, 상세 시트 퀘스트, 미리보기, 도감 카드 | 개발 서버에서 테스트 모드로 전 과정 확인 |
| 3. 기기 확인 | user APK 빌드, 에뮬레이터 위치 이동으로 퀘스트 완료 | 화면 캡처 확인 |
| 4. 1차 베타 | "꼭 참여" 6명 | 설치·첫 해금 문제 없음 |
| 5. 2차 베타 | 조건부 참여자까지 확대 (동의한 사람만 연락) | 4주간 운영 |
| 6. 평가 | 베타 리포트 + 종료 설문(던전 의향 문항 포함) | 다음 방향 결정 |

## 7. 위험

| 위험 | 대응 |
|---|---|
| 마스코트 그림 제작이 늦어짐 | 1단계는 단순한 도형·실루엣 그림으로 시작, 그림은 나중에 교체 |
| 퀘스트 장소 정보가 틀림 (폐업 등) | 제작 직후와 베타 직전 두 번 확인 |
| 베타 참여자가 강원에 갈 일이 없음 | 4주 안에 갈 계획이 있는 사람을 우선 모집, 또는 팀이 직접 방문 테스트 |
| 기록이 기기에만 있어 결과 수집이 어려움 | 좌표 없는 베타 리포트 내보내기 |
| 표본이 작음 | 수치보다 "왜 갔는지/안 갔는지" 인터뷰 병행 |

## 8. 정할 것 (사용자 확인 필요)

1. 시범 시·군 4곳이 위 제안(춘천·원주·강릉·속초)으로 괜찮은지
2. 마스코트 그림은 누가 만드는지 (팀 직접 / 외주 / AI 생성 — AI는 상업 이용 조건 확인 필요)
3. 시범 목표치 (예: 참여자 중 시범 시·군 1곳 이상 해금 비율)
4. 퀘스트 인증 반경 (제안 200m: 위치 정확도 100m + 장소 크기 고려). 해금 판정과 별개의 새 규칙이므로 승인 필요
5. 퀘스트를 하려면 그 시·군이 먼저 해금돼야 하는지 (제안: 퀘스트 인증 지점에서 위치 확인에 성공하면 시·군 해금도 함께 처리)
